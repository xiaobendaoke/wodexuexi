\chapter{总结与展望}
\label{cha:conclusion}

\section{研究总结}
\label{sec:ch6-summary}

本文面向具有截止期限的地面计算请求，研究无人机集群如何通过空间机动形成服务机会，并通过跨节点分工与动态控制利用这些机会。研究按需求可见性、固定快照批量资源竞争和跨时隙排队控制三个层次展开。三者共享实际生成、自然接纳与按时完成的请求语义，但采用的单时隙批量结算与跨时隙持续排队协议有所区别，因此分别建立性能结论，不把绝对指标合并成单一全系统收益。

\subsection{需求感知的集群轨迹与自然接纳}
\label{sec:ch6-observation-summary}

第三章以全部实际生成服务请求为分母定义 DSR，并同时报告接纳率和接纳后完成率，使未覆盖需求的损失进入评价。在保持 $100\,\mathrm{m}$ 服务半径的条件下，将允许感知范围内尚未覆盖 UE 的需求纳入上层预动作观测，通过 Attention-MAPPO 组织邻机与用户信息。独立确认中，候选 DSR 从0.2450增至0.2735（提升2.85个百分点，训练种子配对 $95\%$ 区间为 $[+1.65,+4.06]$ 个百分点），十个训练种子中九个为正，说明规定主场景下需求可见性与轨迹调整具有服务价值。

接纳增加同时改变接纳后的资源压力，因而覆盖改善不能替代执行质量评价。在配对外生流下，基线与候选的实际生成服务请求分母完全一致（均为 $9{,}805{,}180$ 个）。该结果仍受预接纳信息可得性约束，同信息替代结构的探索性比较也没有确立独立注意力优势。本文据此将需求信息增量、聚合结构与物理执行约束分开解释。

\subsection{固定快照中的跨机资源竞争与 MC-ITR}
\label{sec:ch6-snapshot-summary}

第四章在含服务程序缓存与最终批量共享算力的环境中固定位置、请求和历史状态，研究批量算力均分引起的迁移外部影响。MC-ITR 对每个候选分配重新评价整个批次，按超时数与平均归一化时延两层字典序接受严格改善。有限状态空间与严格改善保证相应搜索按无改善或预算条件终止，完整单请求邻域无改善时认证该邻域局部最优，不构成主配置全局最优证明。

主配置平均每快照超时数为2.045，低于迭代对照2.215；九个主场景、UE 与算力变体支持相应质量改善。第三章扩展观测候选轨迹的400个共享快照中，MC-ITR 平均每快照少2.633个超时请求，平均归一化时延降低0.278，含贪心初值的完整调用平均21.876秒。这些结果刻画离线分配余量及其搜索计算代价，反事实分配未回写环境，不能与后续闭环 DSR 相加。MC-ITR 未接入第五章在线策略，也不是其规划蒸馏教师。

\subsection{规划蒸馏与反事实辅助动态排队控制}
\label{sec:ch6-dynamic-summary}

第五章采用独立的动态排队协议，研究突发请求到达、不可变来源与目标、断链进度保留和 EDF 计算共同作用下的联合控制。设计候选级分配与运动双分支策略，以方案条件化和运动期望反馈表达决策关联；通过两轮数据聚合蒸馏规划知识，再使用真实完整轨迹和 CRN 短视界反事实评分辅助 PPO 微调。真实轨迹奖励、辅助分支评分与在线 MPC 目标分别定义，Critic 仅使用真实轨迹 GAE 目标更新。

在三个固定父谱系、八个新工作负载和两个动作流构成的816个配对确认回合中，两轮规划蒸馏学生（48.04\%）相对初始先验选择器（44.30\%）提升3.74个百分点；联合微调 DSR 进一步提高至48.74\%，相对蒸馏学生初值提高0.70个百分点，全31项 DSR 比较的 Bonferroni 区间为 $[+0.39,+0.98]$ 个百分点。通过在完全相同的蒸馏起点与48个确认回合上开展反事实辅助开关的受控消融（$\text{cf}=0$ 对照 $\text{cf}=1.25$），本文明确分解出：在联合微调相对从头强化学习（44.25\%）的 $+4.49$ 个百分点总提升中，两轮规划蒸馏热启动（$\text{cf}=0$ 时 DSR 为48.05\%）贡献了 $+3.80$ 个百分点的基础收益，而共同随机数短视界反事实组辅助项（$\text{cf}=1.25$）贡献了继续超越静态蒸馏学生的 $+0.69$ 个百分点关键收益（去耦微调与无期望向量微调在启用反事实辅助后同样分别提升 $+0.49$ 与 $+0.74$ 个百分点）。与此同时，在同样启用热启动与反事实辅助的微调组内部，联合微调相对去耦微调（$+0.33$ 个百分点，95\% CI $[-0.08,+0.84]$）和切断期望向量微调（$+0.11$ 个百分点，95\% CI $[-0.15,+0.41]$）的全集 DSR 区间仍跨零，同时伴随已接纳任务条件完成率 $+0.89$ 与 $+0.57$ 个百分点的描述性改善，本文保留这一统计边界而不夸大微调内部架构耦合的独立主效应。

测试时，零在线 Engine 前瞻策略通过候选生成与解析特征直接选择动作；神经引导 Top-6 MPC 则使用学习先验参与候选筛选和最终评分。后者 DSR 为49.31\%，相对指定在线规划基线48.56\%提高0.75个百分点，全31项区间为 $[+0.25,+1.42]$。但微调 MPC 相对蒸馏 MPC 的0.21个百分点差尚未显著。两种新控制方式的平均决策耗时分别为0.520秒和0.722秒，低于基线1.602秒，同时仍有16.9\%和24.5\%的决策超过一秒。因此，当前贡献是规定仿真内的规划计算摊销与性能改进，尚非硬实时或现实部署证明。

\section{综合认识与适用范围}
\label{sec:ch6-interpretation}

需求感知、资源分工与队列控制分别揭示了时限服务链条的不同限制。看见需求使轨迹有机会扩大接纳，完整分配评价识别批量外部影响，持续队列模型则把当前选择与后续资源占用联系起来。这些认识可以共同指导方法设计，但各章的数值增益不能独立相加。尤其第五章采用 EDF 计算与跨时隙进度保留，区别于第三、四章最终批量共享算力的单步执行模型。

协议边界需要保持明确。第三、四章采用单时隙内完成接纳与结算的批量共享算力模型，并包含服务程序缓存动态；第五章采用跨时隙保留传输与计算进度的持续队列模型。两类协议均聚焦于通信、计算与截止期服务指标，未建模机身推进能耗或电池电量耗尽退网。若将缓存机制与跨时隙排队协议整合，需要重新冻结目标、状态转移和计数规则后进行闭环评价。

信息与计算条件同样限制外推。第五章依赖集中收集的公开请求和剩余服务状态、冻结上游候选模型及安全启发式，有限候选集不覆盖任意动作。反事实未来由历史预测生成，其固定延续策略与真实学生后续动作不同。统计区间条件于三个固定父谱系，只反映所评估工作负载与动作流变化，不包含完整重新训练的不确定性。第三、四章的单时隙变体敏感性结果属于不同执行协议，不能替代第五章动态排队联合策略的跨场景验证。

本文的机动模型没有建立完整飞行动力学、姿态和扰动模型。第五章的线性全路径几何检查比只检验离散端点更具体，但仍不是飞行安全或稳定性证明。仿真也没有将消息收集、策略推理和实际控制等待写入请求截止期演化，因而平均软件耗时下降不能直接推出现实服务质量不变。

\section{后续研究方向}
\label{sec:ch6-future}

首先，围绕反事实辅助计算预算与候选池规模开展进一步机制检验。第五章已通过相同蒸馏初值与相同确认回合下的受控消融（$\text{cf}=0$ 对照 $\text{cf}=1.25$）证实反事实组辅助项相对纯在策略 PPO-GAE 提供 $+0.69$ 个百分点的净增益；后续可进一步将三步反事实克隆分支消耗的仿真步折算为等量真实环境 rollout 步数，检验相同总仿真调用预算下模型辅助分支与纯环境交互的样本效率折中。对双分支耦合结构，也可在更大候选集合与新增独立训练谱系下继续检验方案条件化与运动期望反馈的适用边界。

其次，研究模型误差与负载变化。改变突发持续时间、幅度、空间热点与任务期限，分别检查需求估计、释放时间近似和固定三步延续产生的偏差。冻结模型零样本评价与重新训练适配应分开报告；新增父谱系用于估计训练不确定性，不能以同一模型更多评估回合替代。对解析近似，应同时报告误差、候选排序和最终决策差异，避免仅用总体相关系数推断控制可靠性。

再次，将决策等待和信息成本写入环境。实际系统需要在请求收集、推理或前瞻超时后继续推进队列，明确旧动作保持、安全回退与异步更新规则，并测量计入等待后的 DSR。对 Top-6 MPC，可在相同候选与评分下改变前瞻预算，研究计算成本是否转化为服务净收益。零在线前瞻仍有解析计算，需在目标硬件上测量完整路径的尾延迟。

最后，可在新协议中重新引入能源、通信和飞行执行约束。应明确推进与通信能耗、剩余电量、返航保留和 UE 能量请求如何改变到达及接纳，统一记录任务损失与平台退出。对覆盖信息设置延迟或缺失，并将位置跟踪误差、传播遮挡和链路中断纳入执行，可检验当前理想协调结果在更实际条件下保留多少。上述扩展需要新的物理协议和独立实验，不能由现有 DSR 与轨迹长度直接推断。

\section{本章小结}
\label{sec:ch6-closing}

本文分别完成需求感知轨迹决策、固定快照截止期优先分配，以及规划蒸馏与反事实辅助动态排队控制的研究。已有证据说明，需求可见性、批量资源耦合和持续排队均会影响集群服务成功；合理利用规划知识并通过环境交互改善策略，能够在规定协议下形成有价值的服务与计算成本组合。进一步的机制、能量和部署结论，仍需在相应匹配对照及真实执行条件下建立。
