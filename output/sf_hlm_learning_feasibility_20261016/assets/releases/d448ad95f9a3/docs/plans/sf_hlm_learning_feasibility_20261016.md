**5．软件费用与评分的统一定义**

计时从部署路径开始准备输入，到输出可执行动作及原合同所含消息序列化完成。包括原合同中的上层推理、图编码、贪心初值、普通修复、策略推理、条件匹配、结果映射和反馈。阶段1还包括门控特征与门控推理。读取文件、恢复离线诊断快照和用于获得真值的 `Env.step` 不计入在线软件费用；策略实现实际需要的复制仍要计入。

共享计算是否复用必须由实现决定并记录。例如门控先算贪心修复才能得到特征，所有分支都已支付这部分费用；学习路径可复用同一中间结果，但不能把它隐去，也不能在账面重复计两次。没有原生门控完整调用的实测前，附加门控费用只能作为显式假设的敏感性分析。

所有正式测量在远程服务器隔离物理核心、数值库单线程的条件下进行，复用原资源租约约束并核实当前核心可用性。各方法相同预热，正式顺序按预定种子打散。记录CPU型号/核心、软件环境、线程数、机器负载、启动身份和每次原始时间。不得挑最快时间、丢慢样本或按结果决定补测；基础设施异常的失效与重测规则需在协议中先定义，原记录保留。

同一分支实例的3次时间都保留，并核对输出一致。费用评分对每次时间分别计算后取平均，不能先取时间均值或p95再代入截止期。主要汇总块级费用指标，另外保留逐次分布；明确p95是块内分位数及其块间汇总，不混作池化p95。

令状态s全部实际生成服务请求数为G_s，分支a对已接纳请求i的实际路径时延为T_{sai}，截止期为D_{si}，逐次完整软件费用为c_{sa}：

`N_raw(s,a) = sum_i 1[T_sai <= D_si]`

`N_fee(s,a) = sum_i 1[T_sai + c_sa <= D_si]`

未接纳服务请求保留在G_s中，成功数为零。G_s从该冻结状态及原计数合同读取/核验，在分支间必须相同，不能使用已接纳数充作分母。随机重复和计时重复先得到该状态/分支的平均成功数，不复制独立样本或重复计分母。

训练块b的主汇总是 `Q_b(a)=sum_s N_fee(s,a)/sum_s G_s`，再对五块等权汇总；原始质量同法计算。该量称为“采样状态的计费后成功率”，不是整回合DSR。另报每状态净成功数差、未接纳比例、UAV实际机队能耗、分配能耗、MBS依赖、调用数和完整软件时间。能耗只反映原仿真，不换算实测机载功率。

物理状态按原模型执行一次；额外软件等待用于事后截止期评分，不回写位置、缓存、电量、队列、奖励或下一状态。后续策略闭环也必须保留这一区分。若要求等待改变后续物理过程，需另立新物理协议，不在本方案中顺手修改环境。

**6．阶段0b的预言机与固定规则**

只对预定候选、所选状态和测量条件报告上限。即使上限很低，也不能证明其他预算、其他算法或跨时隙学习没有空间。

可用特征限定为：批次大小、原观测图的合法去向数量、请求大小/计算量/截止期统计、按原观测预测器计算的服务风险、可见节点负载和容量。若使用贪心预测超时数/配额，必须先支付相应计算。实际执行时延、真实缓存、未来请求和分支实际成功数只能用于离线标签，不能进入特征。

训练标签来自同状态分支的计费后净成功数差；可用差值绝对值作误选权重，零差状态按预定规则回退G。训练和超参数只接触训练折。门控是否调用学习以预定收益规则决定，不能在测试折按最佳DSR挑阈值。

建议外层采用25个“留一个块和一个负载”折：测试单元为 `(块b,负载w)` 的16个状态；训练只使用其他4块×其他4负载的256个状态；同块其他负载与同负载其他块暂不用。全部400状态恰好各有一次外层预测。标准化、阈值校准和任何内层选择仅在训练折；最后按原五块汇总外层结果。这仍是复用开发数据的探索评价，不是25次独立训练确认。

在同一留出状态上，必须比较：始终G、始终学习候选、阶段0b冻结的最好非学习方案、固定规则门控、随机调用门控、学习门控接学习候选，以及同一学习门控接强随机的替换对照。随机调用概率从训练折学习门控的调用比例确定，不能看测试标签；报告测试实际调用比例。若事后严格匹配调用次数，另标为诊断而不是可部署主对照。

每个完整门控方法从准备输入到动作输出重新隔离实测，实际选择的分支执行后获取逐请求质量；不能把离线两条全路径时间相加当成部署费用，也不能因为已经离线算过两个分支就假装部署同时计算它们。门控只执行选择所需的在线计算。

晋级依据为阶段7的实用收益与费用/能耗约束，并报告相对固定规则、随机调用及同门控接强随机的净差。学习门控若只比始终学习好、但不比简单规则好，不能称已证明学习门控必要；同门控接强随机若相当，不能把收益归给PPO配额搜索。

若通过留出筛选，再用全部开发状态按同一训练合同拟合一次最终门控并冻结，不能从25个外层模型中挑最好者。最终模型的训练集表现不当作新增验证。若只剩“学习门控调用非学习求解器”值得研究，单列为新的归因目标，在阶段闸门记录后再设计，不冒充原PPO搜索被挽救。

**9．阶段2：冻结一个候选后做开发闭环**

只晋级一个主候选，另保留最强非学习参照与必要归因组。预算8若已独立通过则直接评估预算8，不必启动门控。门控通过则冻结所有特征、权重、阈值、回退与软件路径。

原五个开发块上建议使用5个未用于门控拟合的开发验证工作负载，每个2回合×1000步。工作负载身份先查重登记，不预填可能已被使用的种子。该轮最多7个预定组，对应最多350回合；最终组数在阶段闸门处冻结，不能为好结果临时加组或删对照。

比较候选、G、冻结最强非学习方法、始终学习及必要的门控归因组。各方法从相同初始条件自行闭环，允许分配通过原环境改变后续缓存、电量和观测；不把不同方法同一步当成同状态。

质量评估与隔离计时分开运行，逐步核对动作、请求顺序、指标、外生流和模型指纹。计时重复若改变分配，必须修复；不得用近似对齐的另一条轨迹收费。原始DSR、潜在固定分母DSR、逐次费用事后DSR、能耗、公平性、MBS依赖和时间共同报告。

这是“策略闭环、费用仍事后评分”。它能检验新策略访问状态后的结果，不能证明软件等待已真实改变后续资源占用或排队。原始实际生成分母有轻微策略依赖性，固定潜在分母复核继续保留。

候选若仍达到+0.5 pp实用目标、方向至少4/5块为正且没有违反冻结约束，才准备独立确认；否则保留开发结果并停止新增主张。开发验证负载一旦看过，也属于已用开发数据，不能移入阶段3。

**10．阶段3：新的独立确认**

确认前锁定最终方法、训练合同、主比较、实用阈值、统计方法、源码摘要、模型选择规则、样本量与种子清单。原十确认块不用于新的候选选择或新增主张确认。

建议起始设计为10个新训练块×5个新工作负载×每负载6回合×1000步；这不是功效保证。根据开发块方差在确认前评估精度，若目标无法合理区分，应在查看确认结果前调整或放弃，不运行到显著为止。

冻结原基座及下层训练合同，在新块重建所需基座与学习策略；非学习方法共享对应块的同一基座，不伪装成独立训练过。门控若采用阶段1开发数据训练后的最终冻结模型，应明确这是固定门控跨新块的确认，不等于门控训练重复；若主张完整门控训练流程的稳健性，需另设每块独立门控训练数据和训练合同。

主比较预先固定为候选相对G，以及相对开发阶段选定的最强非学习可实现方案；使用新块配对差，主比较两项组成Holm族。95%区间、效应量、块方向和精确符号翻转敏感性完整报告。若要声称学习门控或学习配额搜索的独立作用，另设固定规则/随机调用/同门控接强随机的机制比较族，不能事后只报告显著的一项。

建议实用目标：相对G的平均计费后DSR至少+0.5 pp；相对最强非学习方案平均至少+0.1 pp；同时有经预定多重比较处理的正差证据。平均达到0.5 pp且区间下界大于0，只支持“平均达到目标、正向证据成立”；要声称真实优势至少0.5 pp，区间下界也须超过0.5 pp。若声称原始质量非劣，需事先冻结0.1 pp容忍界并按非劣问题判断，不能用不显著代替。

若两种推断方法结论不同，报告检验敏感性，不使用稳健优越的表述。确认失败、区间过宽和费用结果反向都完整交付，不重挑中间检查点。

即使确认通过，论文主张仍限定为原仿真及指定软件测量条件下的费用事后服务评分。等待回写、真实通信、持续队列、真实机载平台和跨时隙新动作均属其他协议。
