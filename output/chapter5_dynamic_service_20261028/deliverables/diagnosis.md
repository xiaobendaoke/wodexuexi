# 第五章策略诊断：边界漂移与下层路由退化

日期：2026-10-30。诊断对象为冻结科学源码 `source_b4b20295` 和已完成的开发阶段最终模型，未修改协议、模型、正式评估或论文正文，没有构造优化器或启动新训练。

## 结论及其强度

已定位两个直接失效模式：上层学到持续向边界偏移的动作，投影后长期停滞；较差训练块的下层在后续训练中退化，将大量原本可改派完成的请求送到传输本身就超时的MBS。

另有一项设计上的信息利用差异：历史控制器聚合所有UAV可见需求，学习actor的需求注意力主要处理本机可见需求，邻机注意力没有传递邻机需求编码。它需要在修复和公平对照中明确，但本次没有证明这是差距的唯一原因。

这些证据足以确定下一轮诊断和修复的优先级，尚未证明某项算法修改已经有效。优化过程为什么形成这些坏策略，仍需要受控的训练诊断，不能仅凭最终行为推断为特定PPO公式错误。

## 诊断范围与可复现性

第一阶段共102项：六种学习/干预方式×五训练块×三个已存在工作负载，另有悬停/历史方法各三个、五块共同快照审计及一次参数/日志审计。轨迹均为D/1.0、开发工作负载0/1/2、repeat=0、1000步。第二阶段增加10项细化检查：每块一个精确轨迹重放和一个共同快照路由审计。

完整策略15条、同上层＋匹配15条、历史参照3条，共33条轨迹的逐步生成数、接纳数、成功数、MBS数与完整分配向量精确复现原记录。重放使用原记录的超时回退事件；其他诊断干预不把新增测量耗时当成正式决策耗时，不能当作新的正式性能评估。

102项主诊断与10项细化诊断全部完成。2744份既有模型、评估、统计和开发门槛文件的前后SHA-256一致；冻结科学源码协议摘要仍为 `a4ffd7991c85f2a2887da47f5fac71b9219517cff496b46822b765f8f08b6639`。数值计算全部在原服务器执行。

## 一、上层已经出现持续边界漂移

五种子×三个工作负载的完整策略重放中：

| 指标 | 结果 |
|---|---:|
| 距任一边界不足1 m的无人机时隙比例 | 79.38% |
| 实际位移不足0.1 m的无人机时隙比例 | 71.87% |
| 指令对应的平均位移 | 4.66 m/架/步 |
| 投影后的平均实际位移 | 0.45 m/架/步 |
| 实际位移与指令位移的平均向量差 | 4.35 m |
| 活跃请求到最近UAV的平均距离 | 222.17 m |

位移向量差不等同于损失的路程，不能简单把两者相减作为执行保留率。边界和避碰投影共同作用于实际动作。

workload=0的五块细化重放中，有74.72%、76.00%、75.48%、91.32%、89.34%的全部无人机时隙同时满足“已在边界附近且仍发出外向指令”。轨迹终点集中到x=50/650或y=50/650的边缘，多个UAV的动作长期保持同方向偏置。

独立运动检查确认：边界处合法内向动作可移动15 m，外向动作按边界约束停留，悬停没有位置漂移。因此没有发现执行器普遍无法离开边界的错误；当前策略经常没有提供有效的离边动作。原投影仍需处理200 m间距，不能简单删除避碰或边界规则来提高完成率。

### 相同请求下的轨迹替换

以下全部为诊断子集，不是上一份完整1110回合结果的替代值。无模型基线在三个工作负载上只计算一次，不充作五次独立训练。

| 轨迹与下层组合 | DSR | 接纳率 |
|---|---:|---:|
| 原完整策略重放 | 21.10% | 26.45% |
| 学习轨迹＋匹配下层重放 | 23.11% | 26.34% |
| 初始位置悬停＋匹配 | 26.72% | 34.54% |
| 历史热点轨迹＋原学习下层 | 27.20% | 40.75% |
| 历史热点轨迹＋匹配 | 30.62% | 40.75% |

更换轨迹及其公开观测聚合方式后，保留原学习下层也能明显提高服务率；使用匹配下层时，学习轨迹仍低于悬停。这支持将上层控制作为首要诊断对象，不能仅通过修下层弥补全部差距。闭环反馈随轨迹/分配而变，表中结果不是固定几何的纯组件效应。

### 评估方式与历史状态

使用匹配下层时，把上层均值动作改为一次固定诊断随机流采样，DSR仅从23.11%变为23.14%，尚未观察到明显恢复。每步清空GRU隐状态，DSR升至24.64%、接纳率28.75%，但仍低于悬停。清零服务反馈得到22.73%。这些都是推理时分布干预，不能直接作为“去GRU训练更好”或“反馈无效”的证据。

同一观察、同一隐状态下清零当前需求特征会改变动作，但多个块对历史隐状态的敏感性更大；结合持续同向漂移，GRU没有在当前结果中表现出预期的需求跟踪收益。不能由输入敏感性大小单独判断组件价值。

## 二、较差种子的下层发生了可定位的路由退化

第2训练块的40个共同快照共有553个接纳请求。所有策略看到完全相同的请求、几何和资源状态：

| 同批次分配方式 | 按时完成数 |
|---|---:|
| 最终图策略 | 332 |
| 该块第51回合保存的早期下层 | 441 |
| 最终独立请求策略 | 403 |
| 最终并行图策略 | 421 |
| 贪心 | 434 |
| 匹配 | 473 |

早期检查点只作事后诊断，不能据此挑选它替换预定最终检查点。相同批次下441→332表明后续训练产生了质量退化，不能将差距仅解释为轨迹或请求不同。

最终图策略分到MBS的200个请求中199个超时，这199个请求的传输时延已经超过截止期。当前继承的回传带宽为750 kHz，配合新协议0.4–0.95 s截止期和1–5 MB任务，不少MBS路线在传输阶段就失去完成可能。

但是，MBS不可按时完成不等于每次选择它都错误：当其他节点也无法接纳更多工作时，调度器可能通过牺牲某些请求减少整体超时。正常种子的少量MBS分配也有这种特征，因此不能仅看MBS比例。

为进一步确认，在相同快照中只允许把原先分到MBS的请求改派到物理可达UAV，且每次只有全批次成功数严格增加才接受。第2块成功数可由332恢复到445，说明至少113个请求的损失可通过改变这部分路由救回。其他块对应结果为420→420、408→413、398→398、434→434。此离线反事实支持“第2块存在明显可避免的MBS路由损失”。

这项改派没有回写任何环境、没有修复部署策略、没有被计入学习算法DSR，更不是全局最优解。

### 辅助线索

第2块在上述快照的批次实际成功比例均值约0.587，最终解码位置的critic值均值约0.719，存在高估迹象；但该状态还有未选择的最后动作，预测与实现值并不完全同义，不能仅凭这个比较认定critic公式错误。

对同一图策略清零动态负载特征会使第2块完成数进一步降至265，其他块也下降。因此不能把负载更新模块简单删掉；它已被策略使用，只是没有防止该块退化。下层改用8次采样的平均成功数仅约339，仍明显低于早期下层和匹配，单纯把argmax改成采样不足以恢复质量。

本次没有重新进行整条串行训练，因此未验证长期浮点差异是否影响优化分支；原加速器短程等价检验不能替代这个问题的完整对照。

## 三、需求信息的实际聚合方式存在差异

代码位置：`utils/dynamic_service_baselines.py`中HistoryController.update对visible沿UAV轴取并集；`marl_models/dynamic_service_hmarl.py`中UE注意力按UAV分批处理，邻机注意力的query仅来自自身节点特征和反馈，没有包含刚生成的需求编码。

在15条完整策略轨迹每25步的600个几何样本上，每架UAV平均直接可见约59.39%的活跃请求，而全部UAV可见并集约91.97%。历史控制器使用后者聚合需求；当前actor主要处理前者，辅以邻机位置/服务压力。

相同外部观察对象不等于相同的需求信息利用。后续应明确是理想协调下共同聚合，还是每机局部信息；再统一算法和对照的规则。这个结构差异与边界漂移同时存在，当前还没有单独训练对照来量化其贡献。

## 四、下一步修复顺序

1. **先处理上层动作与约束的接口。** 保留服务唯一奖励、速度、覆盖和避碰规则；显式提供实际位移/受阻反馈，并设计能表达有效内向移动的约束感知动作方式。先验证贴边、停滞和覆盖指标，再评估DSR，不先增加覆盖奖励或削弱物理约束。
2. **统一需求聚合。** 在已声明的信息和协调预算下，让actor与强对照可利用同一组当前需求，或把对照限制到同一局部信息。不能仅把相同字典传给两种实现就认定信息条件已经等同。
3. **再处理下层训练稳定性。** 明确编码候选节点在暂定负载下的预计时延和截止期余量，诊断更新幅度、策略KL和critic偏差。保持物理mask与超时风险区分，不把“可能超时”悄悄改成不可达，也不通过贪心修复掩盖策略质量。
4. **分层做小规模开发验证。** 先固定共同下层验证上层修复，再在共同批次上验证下层稳定性，之后才恢复双层交替训练。按现有开发数据使用规则记录版本，保留旧失败结果；通过开发门槛前不扩大确认。

这些是基于诊断的修改方向，尚未实施到冻结算法或开始新的候选训练。当前仍不能声称记忆、反馈或图分配已经带来稳定收益，也没有得到复杂度交互结论。
