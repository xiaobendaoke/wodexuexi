# Offload Policy Paper Validity Summary

This note records the current paper-facing interpretation of the lower-level offloading module. It supersedes the earlier wording that described `surrogate_baseline` mainly as a heuristic distillation baseline.

## Current Position

- The lower-level policy should be described as **oracle-guided request-level offloading policy learning**.
- The training procedure is close to imitation / behavior cloning: a lightweight classifier learns labels generated by a more expensive offline oracle.
- The oracle is not a future-information oracle. It uses the current request context: candidate local/cooperative/MBS latency, deadline, queue pressure, MBS load, and cooperative queue-relief benefit.
- The online policy only consumes runtime state features and predicts one of `local`, `cooperative`, or `MBS`.

## Paper Claim Boundary

- Do not claim novelty from joint optimization alone. Prior work already studies trajectory, task offloading, resource allocation, service placement, and caching in unified or two-timescale formulations.
- The defensible novelty is the deployable two-level learning decomposition: attention-MAPPO for upper-level multi-UAV coordination and oracle-guided request-level policy learning for lower-level offloading.
- The main lower-level claim is not that every metric improves simultaneously. The stronger claim is that the enhanced oracle can explicitly compress MBS fallback dependence while keeping latency and deadline degradation bounded.

## Required Evidence

- Report lower-level runtime results with paired seeds, confidence intervals, and paired tests against `heuristic_offloading`.
- Report joint end-to-end evidence with four combinations:
  - `uncoordinated_greedy + heuristic`
  - `attention_mappo + heuristic`
  - `uncoordinated_greedy + oracle_guided`
  - `attention_mappo + oracle_guided`
- Use the same workload seeds, UE map generation, request arrivals, and evaluation length across combinations.
- Treat `rich_reduced_runtime_policy` as an aggressive MBS-reduction ablation, not as the only main lower-level policy.

## Remaining Risks

- If the joint four-way comparison does not preserve the MBS-load reduction or service-quality tradeoff under `attention_mappo`, the paper should present the lower-level result as a controlled request-level improvement rather than a full system-level win.
- If learned-policy fallback counts are nonzero, report them explicitly and explain whether they come from checkpoint loading, feature-family mismatch, or prediction exceptions.
- For ratio metrics such as DSR and MBS load, use bootstrap confidence intervals over paired seeds now; add exact binomial confidence intervals later only if request-level success/total counts are logged.
