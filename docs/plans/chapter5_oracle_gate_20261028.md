# 第五章计算价值诊断协议

日期：2026-10-28。本协议在本轮读取逐状态收益、求解门控选择或绘图之前写定。复用的C0汇总结果已经公开，本轮不是预注册确认试验。

## 问题与范围

只回答现有G和完整解析方法在既定1200个固定状态上的离线选择空间。不改第五章、不训练模型、不重跑轨迹、不修改封存实现。不存在自动启动新上层训练或独立闭环确认的授权扩展。

主参照为C0重新计时的原生完整方法`native_B10`，同实现`B10`作敏感性比较。分别求解，不从二者中事后挑选有利参照。数据来自五个历史开发块，G/解析两种源轨迹各占一半，保留全部状态及每状态每方法三次计时。

## 输入和审计

- 输入为C0 `development_v2/protocol.json`、`fixed_labels/*.json.gz`及其摘要回执、`analysis/summary.json`、完成回执。
- 每状态一个路由决策，在G与完整方法间选择。三次实测费用各自用于该次成功判断，然后取三次结果的均值。路由不按计时重复分别选择，不挑最快一次。
- 核对状态唯一身份、五块各240状态、设计权重25、请求与生成数边界、逐请求截止期与成功标签、时间重复、完整机队能耗、MBS数。重构原C0固定状态的块值并对照原汇总，失败时停止解释。
- 原始文件只读，登记SHA-256。所有派生计算、求解和科学图在服务器完成。本机只编写代码、轻量测试和检查产物。

## 目标与约束

设`x_i=1`表示返回G，`x_i=0`表示运行完整方法。每状态两分支的标签为三次计费成功数均值、完整时间均值、完整机队能耗和MBS数。

块内先按设计权重汇总成功数与实际生成数，求`S/G`；主质量差为五块DSR差的算术均值，单位为百分点。完整时间与能耗先取块内候选/参照比，再跨块平均。补充报告全体请求加权率，但不以其替换原协议主口径。请求、状态、源轨迹和计时重复均不增加独立n。

离线oracle在所有状态上联合选择二值路由，最小化完整时间比，约束：

1. 相对完整方法的DSR损失不超过给定阈值。
2. 相对完整方法的平均块机队能耗比不超过1.05。
3. 相对G的平均块机队能耗比不超过1.05。

质量允许损失网格固定为0.00至0.20个百分点，步长0.01。主要判断点为0.10个百分点、时间比0.80。MBS仅描述性报告，不新增原协议没有的0.3个百分点门槛。

同时求解连续松弛`0<=x_i<=1`作为更乐观的随机路由边界，二值MILP给出逐状态固定路由。记录求解状态、约束残差、目标、界和gap；超时或未证最优不得冒充最优值或不可行证明。主点另对G源与解析源状态分别作敏感性诊断。

## 上界的含义

两分支沿用独立完整调用的原生计费标签，oracle门控和特征费用取零，因此是既有标签上的乐观筛选边界。它没有证明先求G再继续可以零复制地复用初始化，也没有测得部署门控费用。未通过时只能否定同一标签、分布、两分支及约束下的选择空间；通过仅表示值得检查公开特征，不能称在线或闭环收益。

额外费用对截止期成功数具有阈值效应，不能只在最终时间比上加平均开销。本轮如果做非零开销敏感性，应将该费用逐次加入每个请求的原实测费用后重新形成成功标签，并明确其是假定费用而非新测量。
