# 无人机辅助动态权重边缘计算卸载策略研究

王义君\* 王雅出 SHAHD Batool 缪瑞新

(长春理工大学电子信息工程学院   长春   130022)

摘   要：针对无人机辅助移动边缘计算环境下计算资源受限、系统处理任务总开销过高问题，该文提出基于协同缓存自适应的分层多元宇宙优化(CCAH-MVO)算法优化卸载策略。首先，构建微云-边缘-本地3层网络架构，在无人机边缘服务器上预制缓存程序，采用细粒度部分卸载策略，并针对多无人机覆盖的终端设备制定无人机选择策略。然后，提出CCAH-MVO算法协同优化缓存、卸载和资源分配，并引入动态权重机制自适应平衡时延与能耗，得到最优卸载策略。仿真结果表明，所提策略的时延更优、能耗在裕度区内可控，综合性能优于基准卸载策略。

关键词：移动边缘计算；卸载决策；无人机选择策略；动态权重；多元宇宙

## 1    引言

随着物联网(Internet of Things, IoT)技术发展与普及，多元化智能应用层见叠出，对于智能设备的计算资源在实时响应、服务可靠性和网络带宽上的需求提升到一个全新高度。因此，第5代(5G)移动通信与IoT深度结合促成移动边缘计算(MobileEdge Computing, MEC)兴起[1,2]。MEC通过将计算、存储和网络资源下沉至网络边缘，实现数据就近处理，有效缩短数据传输路径并为新型无线通信系统的信道估计与性能优化研究提供重要支撑[3,4]。目前，在智能家居、医疗保健和自动驾驶等场景中展示出巨大的应用价值[5]。然而，MEC严重依赖基站进行部署，使其在偏远地区及特殊场景中面临覆盖盲区与服务局限，不能及时为用户提供计算服务。同时，服务缓存问题也制约MEC的性能发挥[6]。随着小型无人机(Unmanned Aerial Vehicle, UAV)无线通信技术的兴起，UAV-MEC作为一种新型架构，正展现出巨大潜力[7]。它利用UAV灵活部署与广覆盖能力，辅助地面服务器处理密集型任务，显著拓展MEC能力范围[8–11]。因此，研究无人机缓存辅助下的多终端-多服务器移动边缘计算卸载问题具有重要意义。

作为移动边缘计算的关键技术，计算卸载技术在无人机辅助场景下得到广泛研究。为此，研究人员从不同角度提出多种UAV-MEC计算卸载方案。

针对UAV-MEC卸载结构，文献[12]使用本地-无人机-接入点3层网络卸载结构，基于交替优化算法实现总能量消耗最小化。文献[13]针对多用户－单无人机场景基于约束分解多目标进化算法保证能耗降低且无人机安全飞行。但文献[12,13]是多输入单输出场景，对设备被多个无人机覆盖的情况并不适用。

针对UAV-MEC任务卸载模式，文献[14]基于有向无环图的多依赖任务计算卸载，协同优化卸载决策、资源分配和任务调度，但缺乏动态资源优化，文献[15]采用细粒度模型划分，联合顺序图来简化问题，但忽略设备移动性等现实问题。文献[16]采用函数级粒度卸载模式，并基于回溯搜索在线决策算法搜索最优卸载方案，但是对动态环境适应性不足，未考虑多用户间的竞争。

针对优化UAV-MEC卸载问题，文献[17]提出一种面向动态环境的多目标优化策略，提出动态多目标自适应加权粒子群优化算法。文献[18]针对无人机部署时面临高内存、高计算开销问题，提出混合自适应学习框架，能有效寻找最优解，但是算法过于复杂不易实现。文献[19]研究云端-边缘端协同计算卸载方案，只考虑时延对任务卸载的影响。

相较于现有研究，当前UAV-MEC计算卸载方案仍存在诸多局限。卸载结构适配性有限，难以应对多无人机覆盖终端场景；任务卸载模式对动态环境适配不足，未充分考虑资源动态优化、设备移动性及多用户竞争等现实因素；优化算法或复杂度高、不易实现，或单一侧重时延优化，未能有效平衡时延与能耗。为此，本文聚焦多终端设备与多无人机服务器协同场景，引入缓存辅助机制的细粒度卸载方案。(1)当1个终端用户被多架无人机覆盖时，通过无人机选择函数，将任务卸载至选择函数值最高的无人机，该无人机充分考虑实时负载、距离以及综合开销等影响因素；(2)提出基于协同缓存自适应的分层多元宇宙优化(Cooperative Cach-ing-Adaptive Hierarchical MultiVerse Optimizer,CCAH-MVO)算法，在多元宇宙优化算法基础上，引入一种动态权重机制，并融合混合编码方案、约束处理机制和动态环境响应机制，充分适应系统实际约束，最后得到最优卸载策略。对比多种基准方案，本文在构建多无人机协同、缓存受限条件下，所提卸载策略能够有效平衡系统负载，从而在处理任务时实现低时延、能耗可控，并显著降低总开销。

## 2    系统模型及问题描述

## 2.1 系统模型

本文移动边缘计算卸载模型如图1所示。本模型以储备全部数据资源的中央服务器基站为核心，搭配多架搭载服务缓存的无人机及若干移动终端设备，共同构成“微云-边-端”3层卸载架构。移动终端设备借助无线通信链路与无人机建立连接，无人机则通过无线回传链路与中央服务器基站实现通信互联。终端设备任务既可以选择在本地直接运行，也能够将其卸载至无人机边缘节点处进行处理，其中无人机向基站下载程序作为工具去执行任务，最后无人机将计算结果返回给终端设备。

N任务卸载系统中 架无人机表示为集合$N = \{ n _ { 1 } , n _ { 2 } , \cdots , n _ { N } \}$ M， 个地面终端设备表示为集合 $M = \{ m _ { 1 } , m _ { 2 } , \cdots , m _ { M } \}$ ， k 个 任 务 表 示 为$\pmb { L } = \{ l _ { 1 } , l _ { 2 } , \cdots , l _ { k } \}$ ，每个任务都由一个特定程序处理，所有程序表示为集合 $J = \{ j _ { 1 } , j _ { 2 } , \cdots , j _ { k } \}$ ， 而 每个程序大小为 $l _ { j }$ 。基站(Base Station, BS)配备高性能边缘服务器，它可以缓存需要的所有程序，相比之下，由于存储容量有限，每架UAV只缓存部分程序，所以当任务所需程序没有被缓存时，UAV则从BS获取相应程序。

## 2.2 缓存模型

无人机在执行任务前，预先将所需程序存储在无人机搭载的边缘服务器上。使用二进制决策来表明程序是否已缓存，其表示为

$$
c _ { j , n } \in \{ 0 , 1 \}\tag{1}
$$

其中， $c _ { j , n } = 1$ 表示已缓存， $c _ { j , n } = 0$ 表示未缓存。

为最大化实现空间利用率，提出基于效用最大化原则来决定哪些程序被优先缓存，其效用函数表示为

$$
U = \boldsymbol { \varepsilon } _ { t } \cdot \boldsymbol { T } + \boldsymbol { \varepsilon } _ { e } \cdot \boldsymbol { E }\tag{2}
$$

其中， $T$ E为任务完成总时延， 为任务执行消耗总能量， $\varepsilon _ { t }$ 和 $\varepsilon _ { e }$ 为时延权重和能耗权重，满足$\varepsilon _ { t } + \varepsilon _ { e } = 1$ 而对于任意一个程序，则通过估算自身效用提升来决定是否被选择，效用提升可以通过式(3)表示

$$
\Delta U ^ { j } = U _ { 0 } ^ { j } - U _ { 1 } ^ { j }\tag{3}
$$

其中， $U _ { 0 } ^ { j }$ 表示有程序时的效用， $U _ { 1 } ^ { j }$ 表示没有程序时的效用。总潜在效用提升表示为

$$
U _ { j } ^ { \mathrm { p o t } } = \sum _ { \begin{array} { c } { { l _ { i } \in L , \varphi ( l _ { i } ) = j } } \end{array} } \Delta U ^ { j }\tag{4}
$$

## 2.3 通信模型

采用正交频分多址信道访问方案，通过为每个设备分配正交频带资源来实现多设备同时且无干扰的通信，确保视距链路(Line of Sight, LoS)可行性。这里无人机位置由水平坐标 $p _ { n } = ( x _ { n } , y _ { n } )$ 和固定悬停高度 $h _ { \mathrm { u a v } }$ 共同定义，地面设备位置由水平坐标 $p _ { m } = ( x _ { m } , y _ { m } )$ 表示，所以地面设备与无人机之间的水平距离表示为

$$
d _ { m , n } = | | p _ { n } - p _ { m } | | = { \sqrt { \left( x _ { m } - x _ { n } \right) ^ { 2 } + \left( y _ { m } - y _ { n } \right) ^ { 2 } } } ~\tag{5}
$$

在每个任务卸载周期内，无人机和地面设备位置固定，但不同周期之间，它们可能会发生移动。因此，移动后的水平距离为

$$
d _ { m , n } ^ { \prime } = | | p _ { n } ^ { \prime } - p _ { m } ^ { \prime } | | = \sqrt { \left( x _ { m } ^ { \prime } - x _ { n } ^ { \prime } \right) ^ { 2 } + \left( y _ { m } ^ { \prime } - y _ { n } ^ { \prime } \right) ^ { 2 } } ~ .\tag{6}
$$

根据自由空间路径损耗模型，终端设备到无人机的信道增益定义为

$$
h _ { m , n } = \frac { \mathrm { h } _ { 0 } } { h _ { \mathrm { u a v } } ^ { 2 } + d _ { m , n } ^ { 2 } }\tag{7}
$$

其中， $\mathrm { h } _ { 0 }$ 是一个常数，在1 m参考距离下的信道增益。根据香农定理，通信系统频谱效率定义为

$$
\eta _ { m , n } = \log _ { 2 } \left( 1 + { \frac { P _ { m } h _ { m , n } } { N _ { 0 } } } \right)\tag{8}
$$

其中， $P _ { m }$ 为设备发射功率， $N _ { 0 }$ 为无人机噪声功率谱密度。因此，设备到无人机的上行数据速率定义为

$$
R _ { m , n } ^ { \mathrm { u p } } = b _ { m } B \mathrm { l o g } _ { 2 } \left( 1 + \frac { P _ { m } h _ { m , n } } { N _ { 0 } } \right)\tag{9}
$$

其中， $b _ { m }$ 为分配给设备的带宽比例，满足 $0 \leq$ $b _ { m } \leq 1$ B， 为系统总带宽。

## 2.4 计算模型

(1)本地计算：

任务在本地执行时，终端设备的任务执行时延T locm 表示为

$$
T _ { m } ^ { \mathrm { l o c } } = { \frac { W _ { m } } { F _ { m } ^ { l } } }\tag{10}
$$

其中， $W _ { m }$ 为执行任务总CPU周期数， $F _ { m } ^ { l }$ 为终端设备计算能力。执行任务产生的能耗 $E _ { m } ^ { \mathrm { l o c } }$ 表示为

$$
E _ { m } ^ { \mathrm { l o c } } = \kappa \cdot \left( F _ { m } ^ { l } \right) ^ { 3 } \cdot T _ { m } ^ { \mathrm { l o c } }\tag{11}
$$

其中， $\kappa$ 为能耗系数。

## (2)边缘计算：

在这项工作模型中，存在无人机已缓存程序和未缓存程序两种情况，因此分开计算时延和能耗。由于计算结果数据量极小，可视为0，所以假设任务结果下载到终端设备的时延可以忽略。设备上传时延和能耗分别表示为

$$
T _ { m , n } ^ { \mathrm { u p } } = \frac { D _ { m } ^ { \mathrm { i n } } } { R _ { m , n } ^ { \mathrm { u p } } }\tag{12}
$$

$$
E _ { m , n } ^ { \mathrm { u p } } = P _ { m } \cdot T _ { m , n } ^ { \mathrm { u p } }\tag{13}
$$

其中， $D _ { m } ^ { \mathrm { i n } }$ 为任务上传数据大小。

当无人机上未缓存程序时，无人机需要向基站下载程序，则回程延迟和回程能耗分别表示为

$$
T _ { m , n } ^ { \mathrm { b s } } = \frac { l _ { j } } { R _ { \mathrm { b } } }\tag{14}
$$

$$
E _ { m , n } ^ { \mathrm { b s } } = P _ { \mathrm { b s } } \cdot T _ { m , n } ^ { \mathrm { b s } }\tag{15}
$$

其中， $P _ { \mathrm { b s } }$ 为基站在下行回程链路的传输功率。在无人机上执行任务的时延和能耗分别表示为

$$
T _ { m , n } ^ { \mathrm { u } } = \frac { W _ { m } } { s _ { m , n } F _ { n } ^ { l } }\tag{16}
$$

$$
E _ { m , n } ^ { \mathrm { u } } = \kappa \cdot \left( s _ { m , n } F _ { n } ^ { l } \right) ^ { 3 } \cdot T _ { m , n } ^ { \mathrm { u } }\tag{17}
$$

其中， $F _ { n } ^ { l }$ 为无人机计算能 $\mathcal { H }$ ， $s _ { m , n }$ 为无人机分配给设备的计算资源比例 $( 0 \leq s _ { m , n } \leq 1 )$ 。

任务复杂度决定无人机悬停时长，终端移动性及选择策略决定无人机移动距离，共同影响飞行能耗。因此无人机在执行任务时的飞行能耗为

$$
E _ { m , n } ^ { \mathrm { f l y } } = P _ { \mathrm { h } } \cdot T _ { m , n } ^ { \mathrm { u } } + \frac { P _ { \mathrm { f l y } } \cdot d _ { m , n } ^ { \prime } } { v }\tag{18}
$$

其中， $P _ { \mathrm { h } }$ 为无人机悬停功率， $P _ { \mathrm { f l y } }$ 为无人机移动功率 $, v$ 为无人机飞行速度。

由以上可知，任务卸载时延 $T _ { \mathrm { b } }$ 和能耗 $E _ { \mathrm { b } }$ 为

$$
T _ { \mathrm { b } } = T _ { m , n } ^ { \mathrm { u p } } + I \left( c _ { \varphi ( m ) , n } = 0 \right) \cdot T _ { m , n } ^ { \mathrm { b s } } + T _ { m , n } ^ { \mathrm { u } }\tag{19}
$$

$$
E _ { \mathrm { b } } = E _ { m , n } ^ { \mathrm { u p } } + I \left( c _ { \varphi ( m ) , n } = 0 \right) \cdot E _ { m , n } ^ { \mathrm { b s } } + E _ { m , n } ^ { \mathrm { u } } + E _ { m , n } ^ { \mathrm { f l y } }\tag{20}
$$

其中， $I \left( \cdot \right)$ 为指示函数，当括号内条件为真时值为1，否则为0。

## 2.5 细粒度卸载

选用细粒度驱动的部分卸载模式，将单个任务拆解为相互关联的子任务，实现本地执行与边缘卸载的混合部署。任务划分后，有效减少计算时延和传输时延，提升系统整体处理效率。

采用细粒度卸载模式后，将一个任务 $\cdot l _ { i }$ t分为 个子任务，表示为集合 $\cdot l _ { i } = \{ l _ { 1 } ^ { \prime } , l _ { 2 } ^ { \prime } , \cdots , l _ { t } ^ { \prime } \}$ ，依赖关系使用2元变量描述。

$$
f _ { t , t + 1 } ^ { ( i ) } = \left\{ \begin{array} { l l } { 1 , \quad } & { l _ { t } ^ { \prime } \dot { \mathcal { H } } l _ { t + 1 } ^ { \prime } \dot { \Xi } \dot { \Xi } \dot { \Xi } \dot { \Psi } ^ { \perp } \dot { \Xi } \dot { \Psi } \ddot { \Xi } } \\ { 0 , \quad } & { \ddot { \Xi } \dot { \Lambda } \dot { \Psi } } \end{array} \right.\tag{21}
$$

其中， $f _ { t , t + 1 } ^ { ( i ) } = 0$ 表示两子任务无直接依赖关系，$f _ { t , t + 1 } ^ { ( i ) } = 1$ 表示两子任务存在执行依赖关系，遵循前驱子任务全部执行完毕后，后继子任务才能启动的约束规则。2元变量标识子任务执行位置定义为

$$
a _ { t , n } = \left\{ \begin{array} { l l } { 1 , \quad } & { l _ { t } ^ { \prime } \frac { \mu } { \mathbb { E } } \mathbb { H } \frac { \mp \mu } { \pm \chi } \mathbb { E } \lambda \mathbb { A } \mathbb { A } } \\ { 0 , \quad } & { l _ { t } ^ { \prime } \mathbb { A } \mathbb { H } \mathbb { H } \lambda \mathbb { H } \widetilde { \mathcal { I } } } \end{array} \right.\tag{22}
$$

## 3.1 动态权重机制

在无人机辅助移动边缘计算卸载场景中，无人机作为空中边缘节点，其能耗具有阶段性特征。在任务卸载初期，无人机具备充足能耗裕量。若过度强调节约能耗，会因资源分配保守、卸载路径选择妥协等导致时延增加，降低用户体验；但只追求低时延而忽视能耗约束，则当能耗逐渐耗尽时，可能出现服务中断、需频繁切换节点等问题，最终影响系统稳定性与持续服务能力。

因此，通过设定裕度区及对应边缘值，实现能耗充裕重时延，临界切换保节能的目标。为精准量化裕度区内外的优化目标切换，需先建立开销初始计算空间，为动态权重调整和无人机选择提供量化依据。其表达式为

$$
\phi _ { l } = \frac { T _ { l } } { T _ { \mathrm { l o c } } } \left| \overrightarrow { \pmb { m } } \right| + \frac { E _ { l } } { E _ { \mathrm { l o c } } } \left| \overrightarrow { \pmb { n } } \right|\tag{29}
$$

其中， $T _ { l } / T _ { \mathrm { l o c } }$ 为任务卸载时延标幺值， $E _ { l } / E _ { \mathrm { l o c } }$ 为任−→m务卸载能耗标幺值， 和 $| \overrightarrow { n } |$ 为初始权重系数，二者均为正数。

[0, δ]在初始开销矢量空间中，裕度区 为无人机δ能耗充足区间, 为预留部分富裕能耗的临界参考点，为平衡无人机电池健康与任务执行效率，本文取 $\delta = 0$ .8[20]，如图3所示。

## 3.2 无人机选择策略

在无人机辅助移动边缘计算卸载场景中，无人机能耗特性与任务处理的用户体验需求存在关联与权衡。当存在多无人机覆盖单个终端设备时，需要从可用边缘服务器中选定最优无人机来执行任务[21]。在实际运行场景中，无人机负载率及其网络状态变化是影响无人机选择函数的关键因素。当无人机负载率近似为1，此时应避免向其卸载任务。终端设备与无人机距离越近，对应选择函数值越大，该无人机被选中的倾向性越高。为充分利用资源，优先选择在覆盖范围内且信号范围小的无人机。本文改进适配该场景的最优无人机选择策略，并构建无人机选择矩阵为

## 4    协同缓存自适应分层多元宇宙优化算法

在进行任务卸载时，移动终端设备需要选择无人机或本地进行子任务卸载，可将该过程视为不同子任务去寻找最优位置，最后得到完整的最优卸载路径。然而，多元宇宙优化算法虽然适用于全局寻优，但在求解复杂卸载策略时效率不足。因此，本文提出CCAH-MVO算法，引入混合编码方案、约束处理机制和动态环境响应机制。本算法将卸载过程视为子任务寻找最优位置，通过优化宇宙膨胀率，利用白洞/黑洞机制实现宇宙间高效物质传递，并结合虫洞机制在最优解附近精细搜索，使种群不断向低开销区域进化，最终找到最优卸载策略。

# Research on UAV-assisted Dynamic-weight Edge Computing Offloading Strategy

WANG Yijun WANG Yachu SHAHD Batool MIAO Ruixin

(School of Electronics and Information Engineering, Changchun University of Science and Technology, Changchun 130022, China)

## Abstract:

Objective The increasing demands of the Internet of Things (IoT) for computational resources and real-time processing have highlighted the significance of Mobile Edge Computing (MEC). Traditional MEC relies on terrestrial base stations, resulting in coverage blind spots in remote or specialized environments. Unmanned Aerial Vehicle (UAV)-assisted MEC architectures exploit UAVs’ flexible deployment to expand service coverage. However, existing approaches for multi-terminal, multi-UAV scenarios often fail to optimize task offloading latency, system energy consumption, and adaptability to dynamic environments simultaneously. They also overlook optimal UAV selection when terminal devices are covered by multiple UAVs and lack adaptive mechanisms to adjust optimization objectives during task execution. This study addresses these challenges by integrating cooperative caching, offloading decision-making, and resource allocation strategies.

Methods A three-tier microcloud–edge–terminal architecture is constructed, comprising a central cloud, multiple UAV edge servers with caching capabilities, and numerous mobile terminal devices. A cooperative caching mechanism reduces transmission delay during task execution. Task offloading adopts a fine-grained partial offloading mode, dividing complex tasks into dependent subtasks modeled through a Directed Acyclic Graph (DAG). The Cooperative Caching-Adaptive Hierarchical MultiVerse Optimizer (CCAH-MVO) algorithm is proposed. A hybrid coding scheme encodes offloading decisions, caching decisions, and resource allocation uniformly. A dynamic weight mechanism adaptively balances delay and energy consumption according to the system’s real-time energy state. Additionally, a UAV selection strategy is implemented for scenarios where terminals are covered by multiple UAVs. By simulating inter-universe material exchange and local refined search, the algorithm efficiently determines the optimal offloading strategy. MATLAB simulations validate the method under various experimental settings.

Results and Discussions The simulation scenario involves 50 randomly distributed terminal devices and 5 UAVs in a 400 m × 400 m area. UAVs are deployed above terminal cluster centers, while terminals at cluster edges are simultaneously within the coverage of multiple UAVs (Fig. 5). The optimal UAV for each terminal is selected using the UAV selection function (Fig. 6), preventing resource bottlenecks and achieving balanced load distribution. In terms of delay performance, the CCAH-MVO algorithm maintains the lowest task delay across all task volumes, with a gradual increase as the number of tasks grows (Fig. 7). Delay under CCAH-MVO is consistently lower than under fixed-weight strategies across the full task range, demonstrating the effectiveness of the dynamic adaptive mechanism in preserving low latency (Fig. 10). For energy consumption, differences among the algorithms are minor when task quantities are low. Under high task loads, the activation of the dynamic weight mechanism flattens the energy consumption curve (Fig. 8). When the number of tasks reaches 100, total energy consumption under CCAH-MVO is the lowest among all strategies and remains lower than the fixed-weight approach, reflecting effective control under critical energy conditions (Fig. 9). Regarding total system overhead, the CCAH-MVO algorithm consistently achieves the best performance. The gap with fixedweight strategies widens when task numbers exceed 80, illustrating the dynamic weight mechanism’s

collaborative optimization of delay and energy consumption (Fig. 11). Overall, by integrating the dynamic weight mechanism and balancing load through UAV selection, the CCAH-MVO algorithm effectively mitigates resource constraints and high task processing overhead in complex, dynamic UAV-assisted MEC environments. It ensures precise coordination between task delay and energy consumption across different load stages.

Conclusions The proposed CCAH-MVO framework, incorporating a microcloud–edge–terminal architecture, cooperative caching mechanism, fine-grained partial offloading, dynamic weight adjustment, and UAV selection strategy, effectively addresses resource scheduling in complex multi-UAV MEC environments. Simulations show adaptive optimization of objectives, intelligent energy management, low latency, and reduced total system overhead, improving service stability and user experience. This research provides a practical solution for efficient UAV edge computing in dynamic environments. Future work will explore dynamic energy efficiency optimization and multi-node collaboration while maintaining low-latency performance.
